# Testing / Validation Plan

## Pyramid

**1. Pure-logic unit tests (most coverage, JVM, fast)**
- The ported `clean_markdown()` and `chunk()` against the **shared test-vector
  file**: a JSON corpus generated by running the Python originals in the sotto
  server repo over a fixed set of inputs (headings, tables, links, §-citations,
  unicode, the encyclical's hardest paragraphs, pathological whitespace).
  Generation script lives server-side; the JSON is committed in both repos.
  Any intentional pipeline change regenerates vectors in the server repo first -
  the server is the reference implementation.
- Title derivation, estimator median math, state-machine transitions
  (every edge in 11-data-model.md, including illegal-transition rejection).
- Document intake through `Intake.accept` with real byte-array/file streams and
  controlled read/open/close adapters. Cover complete-document trimming, long
  leading/trailing/interior whitespace, exact/over cap, split multibyte and
  supplementary characters, replacement decoding, file/direct BOM policy,
  expected failures, off-main work, closure, and cooperative cancellation.
  Compare accepted stream text against complete String validation. Retain
  independent Oration publication validation tests.
- `DocumentIntakeTest` launches the real Activity for SEND text/stream, VIEW,
  precedence, missing/unsupported payloads, and Write. Resolver suppliers hold
  reads with latches while the UI renders and accepts Back. Recreate unfinished
  reads and completed Confirm, check stale success/failure fencing, saved
  text/title/voice, and no intake-created rows, logs, or narration commands.
- Ordinary narration ownership through attached `narrate`, `stop`, `delete`,
  detach/replacement, observable facts/results, Room rows/logs, and artifact
  bytes. Use local Room databases and temporary real files with a managed
  deterministic synthesizer and the existing encoder/progress/audio seams.
  Test commands through their public outcomes; keep jobs, run tokens, locks,
  and dispatcher choices private.
- Oration publication through `create`, `prepareGate`, and `sweepOrphans` with real
  local Room and temporary files. An internal source publisher has a production
  file adapter and a controlled test adapter that blocks or fails while keeping
  real filesystem effects. Hold publication before row insertion, start cleanup,
  and verify preserved source, one QUEUED row/created log, and later narration.
  Check typed intake/storage failures, pending and renamed source faults, a
  SQLite trigger rejecting the created log (row transaction rolls back), ID and
  directory collisions, abandoned pending/source cleanup, saved gate preference,
  and legacy repair preserving retained row/audio/checkpoint/log data. A publisher
  programming error must remain distinguishable from expected storage failures.
- Download publication through `prepareDownload`, `publishDownload`, and `remove`
  with real Room and temporary files. The narrow staged-file adapter delegates
  real rename/copy/fsync and holds or fails after actual placement. Assert bytes,
  rows, log counts, and outcomes for both publication/deletion orders, sweep
  versus live publication, failure versus a waiting newer attempt, stale targets,
  availability, and late publication after removal plus same-ID recreation.
  Inject partial audio, post-audio/source promotion, and fsync faults, and a
  SQLite trigger rejecting the downloaded log. Preserve preceding finals and
  unrelated files, actual byte length, optional source, and `updatedAt`.
  `SyncCoordinatorTest` holds old final audio before Room commit, coordinates a
  Room transaction and replacement account, submits a newer download, then
  releases the old attempt. Assert old rejection, new success, its actual bytes,
  downloaded row, and exactly one downloaded log. Cancellation and cleanup after
  commit cannot undo publication. Keep transport/session and attached deletion
  integration tests rather than duplicating moved storage implementation tests.
- Confirm caller tests hold a real Room transaction to verify submission stays
  disabled until commit, and force a filesystem failure then retry to verify
  retained name/voice/text, no premature command, and ID-only command delivery
  after success. A committed QUEUED row survives an absent UI command.
- Hold one chunk with a latch or controlled adapter, then request Stop, another
  oration, a busy retry, duplicate same-ID narration, deletion, and
  detach/replacement. Assert no overlapping model or generate lifetime, no
  premature close or file removal, one terminal outcome, and no late autoplay.
  A sleep that happens not to overlap is not evidence of ownership.
- Cover durable FIFO including an older STOPPED/ERROR retry behind newer
  queued work, equal `queuedAt` values ordered by ID, duplicate coalescing,
  detached/missing/COMPLETE/server-only/diagnostic-only admission, Stop before
  model load, missing source, storage full, ordinary failure, a completed final
  chunk, and continued pickup after a queued row vanishes. Check lifecycle and
  deletion logs as well as final states. Observe listen-now only after saved
  durable audio and fence stale events after Stop, deletion, or detach.

- Check `setPlayhead`, `markSynced`, and `setDownloaded` preserve `updatedAt` and
  return affected row counts (`QueuePersistenceTest`), plus `sync`-flavor unit
  suites (`app/src/testSync/`):
  - `SottoApiContractTest`: loopback `ServerSocket` HTTP/1.1 contract coverage
    (token/capabilities, RFC 3986 path encoding and traversal rejection,
    optional `404` vs `200` source text, non-2xx error body draining and temp
    cleanup, `409` `If-None-Match: *` upload conflict retry, `PATCH` rename,
    `401` distinction, and socket close on coroutine cancellation).
  - `SyncCoordinatorTest`: real in-memory Room, temporary files, blocking/failing
    `RemoteServer`, and in-memory `CredentialStore` covering startup/epoch
    fencing, `401` auto-disconnect without clobbering newer sessions,
    single-flight sync coalescing, remote LWW rename surviving frequent playhead
    ticks, external `sync-staging` survival across `sweepOrphans()`, deletion
    cancellation, fresh-row preparation and account-replacement publication,
    upload admission from current Room metadata, transfer sharing and
    reconciliation, identity-fenced linking, and bounded server narration
    polling edge cases.
  - `SyncUiTest`: Robolectric Compose caller coverage for Account connection/sync
    across recreation and off-main disconnect, Library download progress across
    recreation, dedupe, failure toasts, and refresh feedback, live Oration sheet
    selection and upload progress with result toasts, and Confirm capability
    refresh and requestId-matched server narration across recreation.

**2. Instrumented tests (Room + engine, emulator x86_64 debug variant)**
- Resume correctness: kill the process mid-narration at randomized chunk
  boundaries; assert byte-identical output versus an uninterrupted run (the
  server proved this property; the app must too).
- Room migrations from schema v1 forward, orphan-sweep behavior.
- Schema-v1-to-v2 migration preserves metadata, listening position, chunk and
  byte progress, and accumulated narration time; `queuedAt` starts at
  `createdAt`. Interrupted ordinary recovery keeps queue order/progress,
  excludes the reserved `gate`, and changes an interrupted gate to STOPPED.
  Recovery is once per process, not once per Android-owner attachment.
- Synthesis runs with a tiny stub model in CI (real Kokoro is too heavy for
  emulator CI); real-model correctness is a device-matrix item.

**Ownership scope**: ordinary and diagnostic callers share the retained worker.
`NarrationCoordinatorTest` covers contention in both arrival orders, waiting
ordinary retries and FIFO, gate reset/delete while blocked and after writer
drain with callbacks queued, thread reload,
diagnostic Stop/supersession, Lab detach, media-owner replacement during a gate,
saved source, and legacy checkpoint recovery. Controlled adapters assert one
model/generate lifetime, no premature release/mutation, and no late callback.
Diagnostic verdict tests await callback delivery separately from completed Room
facts because verdict enqueueing follows lifecycle persistence.
Measurement tests use fixed clock/battery/thermal/memory observations and known
arithmetic. Keep independent `NarrationEngine` durability/resume tests.
`NarrationCoordinatorTest` also distinguishes the execution clock from wall
time for both ordinary and gate lifecycle/progress/chunk/outcome writes. Its
ordinary listen-now observation receives the first saved durable row once per
run; gate observations retain progress content and the terminal time detail.
`OrationNarrationContractTest` exercises attached commands with real Room and
temporary files for model/encoder construction, encoding after a saved chunk,
storage full, gate synthesis failure, and gate source preparation failure.
It asserts rows/logs, retained bytes, diagnostic errors/verdicts, and continued
ordinary pickup. A controlled previous-model close receives Stop or detach
before release, proving that no replacement model or sink is constructed.
Gate early Stop still happens after model loading and before preparation, and
a completed final chunk still wins over Stop. These tests cover shared durable
execution without calling its internal operation directly.
`DiagnosticControlSpecRegressionTest` retains the review regressions for a
stopped measurement summary and thread reload with waiting ordinary work.
`NarrationCommandsTest` exercises the actual Lab gate playback/reset controls
and deletion followed by playback of a recreated gate in the same media owner.
`OrationPlaybackTest` drives the same play, listen-now, stop-for-deletion, sleep,
and close interface as that owner, using real Room rows, temporary audio, and a
controlled output adapter. Controlled dispatchers and the Robolectric Main
looper hold real lookups, ticks, deadlines, and persistence to cover both lookup
orders, explicit/automatic selection, coherent cross-Oration positions, unchanged
and growing audio including the final tail, current pause/seek/speed, deletion
and gate recreation, queued deadline replacement/cancel, close with pending work,
and FIFO positions across replacement owners. Assert output effects, saved
positions/logs, and drain completion rather than private epochs, jobs, or queues.
Hold accepted writes across a return to the previous Oration and owner
replacement; selection must restore the latest accepted position before drain.
Keep actual Media3 command-entry, sleep, exported rejection, deletion, Lab
reset (including unattached `ResetGate` clearing `PlaybackPersistence`),
real `MediaController` `15,000 ms` skip increments and `sessionExtras` sleep sync,
and `MediaSession` controller authorization checks (same-UID, verified
trusted including `SYSTEM_UID` and unresolvable UID packages, negative-UID
internal `MediaSessionService` intents in `onGetSession`, and untrusted or
UID-mismatched rejection across `onGetSession` and `MediaSession.Callback.onConnect`
with notification and `InAppNarrationService` behavior retained) alongside these
contracts, and independent durability/sync tests. Also verify closed-owner
`stopForDeletion` invalidation and sleep-timer `sessionExtras` publication across
arm, replace, cancel, expiration, and close in `OrationPlaybackTest`.
`OrationPlayerTest` covers `SavedOrationPlayer` against real Room/temp `source.md`/
`PlaybackPersistence` with controlled `PlayerTransport`/`PlayerCommands` for pre-load
timeline synthesis, source reload on download flip, cross-Oration isolation,
`STATE_ENDED` catching-up vs zero replay, sleep-timer extras sync, active-only
250 ms ticker lifecycles, `Missing` cleanup, and cancellation on close.
`PlayerScreenTest` covers `DropCapText` idempotent updates (`bodyColor`/`bodySizeSp`/text)
and `PlayerScreen` Robolectric Compose behavior via `OrationPlayer.setFactoryForTest`
(pre-load display, `PlayerTimeline` leaf isolation, scrub-on-release touch and
`SetProgress`, transport/speed/sleep delegation, catching-up/stop-narration,
`Missing` view, and `close()` on Back).
`DiagnosticResumeTest` exercises Room, real ADTS encoding, shared gate ownership,
reset, legacy source fallback, process recovery, and byte-identical resume with
crash garbage. Existing Room resume/migration instrumentation remains required.

## Merge criteria

- JVM + instrumented suites green in CI.
- Both flavors' JVM tests and Android lint pass. Run screenshot verification
  with recording disabled so tests compare against the committed images.
  Preserve About/flavor provenance and non-exported command-routing coverage.
- Existing manifest guards pass for both flavors: local has neither INTERNET
  nor ACCESS_NETWORK_STATE; sync adds INTERNET only (ADR-004/ADR-007).
- Test-vector file hash matches the server repo's published hash (drift alarm).
- No new lint errors. The separate ktlint setup/documentation issue is #7;
  ownership validation does not depend on a nonexistent ktlint task.

The CI-equivalent JVM/lint/screenshot check is:

```sh
./gradlew lintLocalDebug lintSyncDebug testLocalDebugUnitTest testSyncDebugUnitTest -Proborazzi.record=false -Proborazzi.verify=true
```

Run relevant Room migration and engine/adapter instrumentation on an emulator
and record actual results or environment blockers in `_state.md`. Emulator
checks establish behavior, never real-model throughput.

## Release criteria (adds to merge criteria)

- PRD acceptance pass on both physical devices.
- A forced-kill resume test on a real >10,000-word document.
- One full release-pipeline dry run (signed APK installs and upgrades over the
  previous release without data loss).
